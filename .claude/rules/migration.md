# DB 마이그레이션 규칙 (Flyway)

- 위치: `backend/src/main/resources/db/migration/`, 이름 `V<번호>__<설명>.sql` (예: `V1__init.sql`, `V2__add_post.sql`). 번호는 기존 최대값 + 1.
- **적용된 마이그레이션 파일은 절대 수정하지 않는다** — 체크섬 불일치로 부팅이 실패한다. 고칠 게 있으면 새 파일로.
- 모든 DDL은 멱등: `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`.
- 엔티티 변경과 마이그레이션은 **같은 커밋**. `ddl-auto=validate`라 어긋나면 앱이 뜨지 않는다.
- 모든 테이블은 `BaseEntity` 컬럼을 가진다:
  ```sql
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  created_at  TIMESTAMPTZ NOT NULL,
  updated_at  TIMESTAMPTZ NOT NULL,
  deleted_at  TIMESTAMPTZ
  ```
- 관계는 FK를 쓴다(S2 선택 규칙이 꺼져 있음). FK 컬럼엔 인덱스를 함께 만든다.
- 소프트 삭제된 행을 고려한 유니크 제약은 부분 인덱스로: `CREATE UNIQUE INDEX IF NOT EXISTS ... WHERE deleted_at IS NULL`.
- 개인정보 컬럼은 탈퇴 시 삭제·익명화 대상임을 주석으로 표시한다(루트 §3-17).
